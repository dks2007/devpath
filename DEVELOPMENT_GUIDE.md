# Як розвивати DevPath

Для першої зміни відредагуй пояснення запитання у `src/data/javascript/variables.ts`. Відкрий перший урок JavaScript, почни тест і перевір відповідь. Так можна побачити весь шлях від рядка в модулі даних до тексту на сторінці. Нижче наведені кроки для більших змін.

## 1. Додати курс

1. Обери постійний короткий ID для URL, наприклад `typescript`. Створи папку `src/data/typescript/`.
2. Додай перший урок за інструкцією нижче. У `index.ts` цієї папки експортуй об’єкт типу `Course`. Порядок масиву `lessons` визначає програму курсу, кнопку наступного уроку й рекомендацію на панелі.

   ```ts
   import type { Course } from '../../types/course'
   import annotations from './annotations'

   export const typescript: Course = {
     id: 'typescript',
     title: 'Основи TypeScript',
     description: 'Навчися описувати дані та перевіряти типи до запуску програми.',
     lessons: [annotations],
   }
   ```

3. Імпортуй `typescript` у `src/data/index.ts` та додай його до масиву `courses`. Він з’явиться в каталозі за адресою `/courses/typescript`. Сторінки курсу й уроків вже приймають ID як параметри маршруту.
4. Для власної обкладинки додай зображення `public/art/typescript.jpg` і новий ID до переліку обкладинок у `CourseCard.tsx`. Для курсу без зображення картка покаже піктограму книги. Назву відзнаки за повне завершення курсу можна налаштувати у `masteryTitles` в `src/domain/achievements.ts`.
5. Відкрий картку й пройди перший урок. Новий курс має власну сторінку, частку завершених уроків і відзнаку за опанування.

## 2. Створити урок

1. Візьми за основу невеликий модуль уроку в папці відповідного курсу. Назви файл за темою. Приклад із попереднього розділу потребує файлу `annotations.ts` з `export default` для об’єкта типу `Lesson`.
2. Задай унікальний `id`, наприклад `ts-annotations`. Заповни `title`, практичну мету в `summary` та орієнтовний час у хвилинах у `minutes`.
3. Додай навчальні блоки у `sections`. Кожен блок має заголовок `heading`, пояснення `body` та необов’язковий рядок `code`. Наприклад, спочатку постав задачу про баланс балів, потім розбери тип `number`, а наприкінці запропонуй спрогнозувати результат зміни.
4. Заповни `questions` п’ятьма запитаннями. Імпортуй новий урок у `index.ts` курсу й встав у потрібне місце масиву `lessons`.
5. Відкрий урок прямим посиланням, онови вкладку, пройди тест і повернися до програми курсу. Номер уроку може змінюватися разом із порядком. Його ID має залишатися стабільним, оскільки він записаний у резервних копіях користувачів.

## 3. Додати тестове запитання

Запитання зберігається біля матеріалу, який воно перевіряє. Приклад об’єкта для `questions` у новому уроці:

```ts
{
  id: 'ts-annotations-q1',
  prompt: 'Який тип описує кількість завершених уроків, якщо значення дорівнює 3?',
  options: ['string', 'number', 'boolean', 'null'],
  correctIndex: 1,
  explanation: 'Числове значення 3 має тип number. Лапки перетворили б його на рядок.',
}
```

1. Сформулюй умову так, щоб її можна було зрозуміти на сторінці «Мої помилки». Значення змінних, межі циклів і потрібний результат варто навести в самому запитанні.
2. Признач глобально унікальний ID. Для нової задачі потрібен новий ID, адже старий може вже посилатися на конкретну помилку учня.
3. Перевір кожен варіант. Перший має індекс 0. Після перестановки варіантів онови `correctIndex`, пройди тест і перевір текст пояснення.
4. Поточний формат курсу передбачає п’ять запитань на урок. Якщо свідомо змінюєш довжину тестів, зміни відповідну перевірку каталогу та приклади граничних оцінок у `tests/learning.test.ts`. Оцінювання в `gradeQuiz` уже використовує фактичну кількість запитань.

## 4. Додати досягнення або змінити XP

1. Визнач вимірювану умову. Наприклад, для відзнаки за п’ять завершених уроків джерелом істини є кількість унікальних ID у `completedLessons`.
2. У `getAchievements` в `src/domain/achievements.ts` додай правило до масиву результатів. Локальна функція `achievement` обмежує показаний прогрес ціллю та визначає, чи відкрито нагороду.

   ```ts
   achievement('five-lessons', 'Дослідник', 'Заверши 5 уроків.', completed.size, 5)
   ```

3. За бажанням додай символ і колір для `five-lessons` у `src/components/AwardBadge.tsx`. Для невідомого ID вже передбачено базову піктограму.
4. Додай до `tests/learning.test.ts` перевірки для чотирьох і п’яти завершень. Онови очікувані списки у перевірках, де нова відзнака тепер також має відкриватися.
5. Для зміни винагороди чи кроку рівнів відкрий `src/domain/xp.ts`. Поточні значення становлять 100 XP за перший успішний тест уроку та 500 XP за рівень. Оскільки баланс обчислюється, зміна формули вплине також на старий прогрес. Для збереження історичних тарифів знадобиться окрема версія правил або журнал нарахувань.

## 5. Змінити дизайн

1. Почни зі змінних у `src/styles/base.css`. Наприклад, `--surface` описує поверхню картки, `--text` використовується для основного тексту, а `--border` задає межі. У блоці для темної теми є інші значення тих самих змінних.
2. Для зміни навігації відкрий `shell.css`; панель, обкладинки та відзнаки оформлено у `dashboard.css`. Уроки, тести, помилки й налаштування мають спільні стилі в `src/pages/learning.css`.
3. Для нового елемента дії використай наявні класи `button primary` або `button secondary`. Посилання `Link` обирай для навігації, а `button` для дії на поточній сторінці.
4. Увімкни обидві теми, звузь вікно до 390 px, збільш масштаб тексту та пройди елементи клавішею Tab. Фокус має залишатися видимим, довгі умови запитань мають переноситися.

## 6. Додати сторінку

1. Створи компонент у `src/pages/`. Для однакового заголовка й опису використай `PageHeading`.
2. Імпортуй компонент у `src/App.tsx` і додай `<Route path="statistics" element={<Statistics />} />` всередині батьківського маршруту з `Shell`. Оболонка вставить компонент у свій `Outlet`.
3. Якщо сторінка має бути у головній навігації, додай запис до `navigation` у `src/components/Sidebar.tsx`. Для внутрішньої сторінки, яка не входить до меню, також задай її назву та шлях у хлібних крихтах у `Shell.tsx`.
4. Отримуй стан через `useProgress()`. Для статистики достатньо читати дані провайдера. Якщо сторінка змінює прогрес, додай дію провайдера і винеси її навчальне правило в `domain/`.
5. Перевір відкриття із меню, перезавантаження за прямою адресою і кнопку «Назад» браузера.

## 7. Підключити бекенд поступово

1. **Почни з контракту.** Опиши, які дані повертає Node.js API для каталогу, уроку й прогресу. Збережи стабільні ID з поточного каталогу. Додай серверну перевірку вхідних даних. TypeScript перевіряє код під час розробки, а HTTP-запит приходить під час виконання.
2. **Підключи обліковий запис.** На сервері визначай користувача за сесією. У PostgreSQL можна зберігати завершення з унікальною парою `(user_id, lesson_id)`. Повторна відправка успішного тесту тоді дасть одне завершення.
3. **Додай адаптер API у `services/`.** Почни з читання прогресу після входу. Потім підключай відправлення спроб і позначення помилок. `ProgressProvider` може надавати ті самі дані сторінкам та окремі стани завантаження, збереження й помилки. Локальний адаптер залишиться доступним для гостьового навчання.
4. **Визнач правила синхронізації.** Для завершень природне об’єднання за ID. Для помилки, яку повторно відкрили на одному пристрої й опрацювали на іншому, потрібні версія запису та узгоджений порядок подій. Так само опиши, як поширюється скидання прогресу. Перевір повторну відправку запиту після втрати з’єднання.
5. **Перенеси авторитетні перевірки на сервер.** Для платного курсу сервер має перевіряти право доступу перед видачею матеріалів. Якщо результат впливає на сертифікат або оплату, клієнт надсилає вибрані відповіді, а сервер перевіряє їх і нараховує XP. Для таких курсів ключі відповідей та закриті матеріали потрібно прибрати зі статичної збірки.
6. **Перевір перший вертикальний сценарій.** Пройди один урок після входу, повтори відправлення, відкрий свій профіль на іншому пристрої та звір XP. Чисті функції оцінювання і наявні тести можна використати спільно на клієнті й сервері.

Після кожної завершеної зміни виконай `npm test` і `npm run build`. Для пояснення архітектури на співбесіді обери одну дію, наприклад «перевірити відповідь», і простеж, які дані переходять від сторінки до доменного правила, сховища та оновленої картки на панелі. [Схема проєкту](./ARCHITECTURE.md)
