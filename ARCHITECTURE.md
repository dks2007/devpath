# Архітектура DevPath

DevPath доставляє курси разом зі статичною збіркою. Браузер відображає уроки, оцінює відповіді й зберігає результати на цьому пристрої. Щоб простежити весь шлях однієї відповіді, почніть з `LessonQuiz`, перейдіть до `useProgress` і відкрийте `domain/quiz.ts`.

## Карта проєкту

| Місце | Призначення |
| --- | --- |
| `index.html`, `src/main.tsx` | HTML із метаданими й точкою входу. React підключає стилі, маршрутизатор і спільний стан. |
| `src/App.tsx` | Таблиця маршрутів і сторінка для невідомої адреси. |
| `src/components/` | Спільні елементи, зокрема оболонка `Shell`, навігація `Sidebar`, заголовок `PageHeading` та індикатор `ProgressBar`. |
| `src/pages/` | Сторінки огляду, каталогу, курсу, уроку, досягнень, помилок і налаштувань. Компоненти конкретного навчального сценарію зібрано в `pages/learning/`. |
| `src/data/` | Реєстр курсів і папки з навчальними матеріалами. Кожен урок має власний файл. |
| `src/types/` | Контракти вмісту, прогресу й досягнень, спільні для інтерфейсу та правил навчання. |
| `src/domain/` | Оцінювання тесту, оновлення навчального прогресу, формула XP і правила відзнак. |
| `src/hooks/useProgress.tsx` | React-контекст, який надає сторінкам актуальний прогрес і дії для його зміни. |
| `src/services/` | Розбір і перевірка резервної копії та адаптер браузерного сховища. |
| `src/utils/activity.ts` | Ключі локальних календарних дат, серія активних днів і підписи тривалості. |
| `src/styles/`, `src/pages/learning.css` | Загальні стилі й теми, оболонка, огляд та оформлення навчальних сторінок. |
| `tests/` | Автоматизовані перевірки правил, зв’язності каталогу й збереження. |
| `vite.config.ts`, `tsconfig.json`, `vercel.json` | Збирання React, перевірка типів, відкриття внутрішніх адрес на статичному хостингу. |

## Як URL обирає сторінку

`BrowserRouter` у `main.tsx` стежить за адресним рядком та історією браузера. Компоненти `Link` і `NavLink` змінюють URL усередині застосунку. `Routes` у `App.tsx` підбирає вкладений маршрут, а `Outlet` в оболонці відображає потрібну сторінку поруч зі спільною навігацією.

| Шлях | Зміст |
| --- | --- |
| `/` | Особистий огляд навчання |
| `/courses` | Каталог |
| `/courses/:courseId` | Програма курсу |
| `/courses/:courseId/:lessonId` | Матеріал уроку, тест і результат |
| `/achievements` | Доступні й заблоковані досягнення |
| `/mistakes` | Запитання для повторення й опрацьовані запитання |
| `/settings` | Тема, резервні копії та скидання |

Наприклад, `/courses/javascript/js-variables` передає через `useParams()` ідентифікатори курсу та уроку. Сторінка перевіряє, чи належить урок цьому курсу. Для помилкової адреси вона показує повідомлення та посилання для повернення. Після прямого відкриття URL хостинг віддає `index.html`, а React повторює цей самий пошук.

## Як компоненти обмінюються даними

Матеріали імпортуються з `src/data`. Сторінка уроку передає об’єкти `course` і `lesson` через властивості компонента (props). У `LessonQuiz` поточне запитання, вибраний варіант і відповіді цього проходження живуть у `useState`. На оновленій сторінці учень починає незакінчений тест спочатку. Уже підтверджені помилки й завершені уроки зберігаються.

Завершені уроки потрібні також огляду, курсу й досягненням. Тому `ProgressProvider` над усіма маршрутами надає їм один знімок прогресу через `useProgress()`. Сторінка викликає дію, провайдер залучає функції з `domain/` і сервіс збереження, а React оновлює залежні компоненти.

## Від відповіді до нагороди

1. Коли учень перевіряє варіант, `recordAnswer` знаходить запитання та перевіряє індекс. `recordAttempt` збільшує кількість відповідей за місцевою датою. Помилка додає запис зі статусом `resolved: false`. Повторна помилка на вже опрацьованому запитанні знову відкриває його.
2. Після останньої відповіді `finishLesson` передає в `gradeQuiz` увесь масив вибраних індексів у порядку запитань. Для кожного запитання має бути рівно один допустимий індекс. Прохідний результат — щонайменше `ceil(кількість запитань × 0.8)` правильних відповідей. Для п’яти запитань це чотири.
3. Успіх додає ідентифікатор уроку до `completedLessons` один раз. `calculateXP` множить кількість різних завершених уроків на `XP_PER_LESSON`, зараз це 100. Два успішні проходження одного уроку дають разом 100 XP.
4. `getAchievements` обчислює для кожної відзнаки поточне значення, ціль і стан. «Перший крок» відкривається після першого уроку, «Наполегливий» після десятого. Для «Майстер JavaScript» і «Майстер Python» функція рахує завершені уроки саме відповідного курсу. «Легенда DevPath» потребує 1000 XP.
5. У розділі помилок учень повторно обирає варіант. Після правильної відповіді він може натиснути «Позначити як опрацьоване». `resolveAnswer` ще раз перевіряє відповідь і змінює статус у наявному записі. XP залежить тільки від завершених уроків.

Прогрес із дев’яти уроків JavaScript та одного Python дає 1000 XP й відзнаки за десять уроків і тисячу балів. Обидва курсові досягнення залишаються заблокованими. Цей випадок покриває тест, бо загальна кількість уроків збігається з довжиною одного курсу.

## Як працює збереження

`ProgressStorage` читає і записує один ключ `devpath.progress.v1` у `localStorage`. Ключ належить конкретному браузерному профілю та джерелу сайту. Бекенд і обліковий запис для цього відсутні. Наступне відкриття сторінки відновлює перевірений знімок. Події `storage` оновлюють відкриті вкладки цього джерела.

Файл резервної копії має той самий формат. Наприклад, такий файл описує завершення першого уроку з одним запитанням для повторення.

```json
{
  "version": 1,
  "theme": "light",
  "completedLessons": ["js-variables"],
  "mistakes": [{ "questionId": "js-variables-q1", "resolved": false }],
  "activity": { "2026-11-19": 5 }
}
```

Імпорт замінює поточний знімок після повної перевірки. `parseProgress` приймає JSON до 1 МіБ, звіряє версію, тему, типи полів, унікальність і відомі ідентифікатори, реальність календарних дат та цілі додатні лічильники. Потім він створює об’єкт із перевірених полів. XP і відзнаки обчислюються заново.

Якщо запис у сховищі пошкоджено, сервіс зберігає оригінал, а нові дії тримає в пам’яті вкладки. Користувач може експортувати поточну сесію, імпортувати справну копію або підтвердити скидання. За недоступного сховища чи помилки запису інтерфейс повідомляє про необхідність експорту перед закриттям вкладки. Скидання створює порожній прогрес зі збереженням вибраної теми.

## Типи й перевірки

`Course` містить упорядкований масив об’єктів `Lesson`. Урок має пояснення та масив `Question`. Наприклад, `section.code?: string` дозволяє пропустити код у текстовому розділі, а `correctIndex: number` указує на позицію правильної відповіді. Строгий режим TypeScript підсвітить пропущений заголовок або рядок замість числового поля під час `npm run build`.

Вміст файлу з диска надходить як `unknown`. Типи TypeScript існують на етапі розробки, тому під час роботи браузера потрібна окрема перевірка `parseProgress`. Приклади коду відображаються як текст у `<pre><code>`. Вибір відповіді порівнює індекси.

## Як працюють автоматизовані тести

`npm test` запускає Vitest один раз, а `npm run test:watch` повторює потрібні перевірки після редагування. У `tests/learning.test.ts` перевіряються каталог, граничні оцінки 3/5 і 4/5, повторні завершення, відзнаки та життєвий цикл помилки. `tests/storage.test.ts` перевіряє імпорт, повторне відкриття, помилки доступу, збереження пошкодженого оригіналу й відновлення після переповнення сховища. Невеликий замінник `localStorage` на базі `Map` дає змогу моделювати ці відмови.

Функції домену отримують входи через аргументи й повертають результати. Однакові відповіді та набір завершень приводять до однакових результатів. Такий поділ дозволяє перевіряти правила без браузера, змінювати оформлення без зміни правил і поступово додати віддалене сховище за наявним API провайдера.
